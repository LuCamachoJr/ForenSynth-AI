# v2.4.0 beta — Evidence review release

Status: implementation ready for review; not a production validation claim.

## Delivered

- Installable Python package, CLI, and Windows/Linux Tkinter GUI; Python 3.11+.
- Desktop build workflow, distribution SHA256SUMS, run verification, and deployment guide.
- Existing detection JSON/JSONL input and optional Chainsaw EVTX source mode.
- Full source preservation, SHA-256 artifacts, canonical JSON pointers, run manifests.
- Versioned validated evidence schema; individual/aggregate normalization.
- Unique events distinguished from detection matches, host/user/process extraction.
- Explicit missing-field reasons; no timezone or observation timestamp invention.
- AI selection protects high/critical records and reports all omissions.
- Offline default; optional structured AI with evidence-reference validation.
- Per-request/total estimated token reservations and request caps; no hidden retries.
- Recorded successful-response usage and configurable pricing (unknown by default).
- Escaped HTML and CSV formula protection; all parsed evidence retained.
- Minimal STIX 2.1 observations/behavior notes and explicitly reviewed indicators.
- Optional pinned ATT&CK bundle import; no fabricated attack-pattern mappings.
- Blocking tests and lint for the active v2.4 package.

## Review gates

Human review should assess the schema, privacy policy, sampling choices, STIX semantics,
and whether pending findings are adequately distinguished from confirmed conclusions.
Run with stable EVTX and the deployed Chainsaw version before using the hunter operationally.
Exercise the configured model in a small authorized lab before enabling cloud processing
on sensitive cases. No live API calls were required for the automated test suite.

Before promoting beyond beta, compare benign/malicious/simulated ground-truth datasets
against manual analyst reports. Measure critical misses, unsupported assertions,
evidence-reference correctness, and analyst time including correction effort.

## Migration

Use `pip install .` for offline processing or `pip install '.[llm]'` for cloud synthesis.
New entry point: `forensynth`; legacy snapshot scripts are unchanged.
`--input`, `--html`/`--make-html`, `--export-evidence-csv`, and `--export-stix` are supported.
`--integrity`, `--sample-step`, `--chart-style`, `--two-pass`, and `--run-tests` are not
v2.4 flags. Hashes are always recorded; use `python -m pytest` for tests. AI is explicitly
opt-in with `--ai cloud`; report construction does not use an unchecked final LLM merge.

The richer v2.4 `evidence.json` object is not compatible with legacy evidence formats.
Its schema is versioned separately to support deliberate future migrations.
